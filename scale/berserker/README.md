# Berserker File Activity Performance Testing

This directory contains resources for running file activity performance tests using real workload generated by berserker, as opposed to fake workload generated internally by the sensor.

## Overview

**Berserker** is a Rust-based load generator that creates real file operations. These operations are detected by eBPF collectors (via the fact container), collected by the collector DaemonSet, and reported to the sensor, exactly as would happen in a production environment.

This provides more realistic performance measurements compared to fake workload testing, where the sensor generates synthetic events internally.


## Workload Files

Each `.ber` file defines a berserker workload that generates file activity events at a specific rate. The workloads are configured with:

- **workers**: 2 concurrent workers per pod
- **duration**: 0 (infinite - runs until pod is deleted)
- **path**: `/tmp/data/` (directory for file operations)
- **rate**: Events per second per worker (exponential distribution)

### Rate Calculation

The event rates assume a **3-node cluster** with berserker running as a DaemonSet (1 pod per node):

```
rate_per_worker = target_total_rate / (3 nodes × 2 workers)
```

Examples:
- 100 events/sec → rate = 100 / (3×2) = 16.67
- 1000 events/sec → rate = 1000 / (3×2) = 166.67
- 5000 events/sec → rate = 5000 / (3×2) = 833.33

**Note**: If your cluster has a different number of nodes, you may need to adjust the rates in the `.ber` files accordingly.

## Deployment Scripts

The deployment scripts are located in `scale/dev/`:

- **`deploy-berserker.sh`** - Deploy a berserker workload as a DaemonSet
- **`cleanup-berserker.sh`** - Remove berserker resources
- **`perf-test-file-activity-berserker.sh`** - Main test script (replaces `perf-test-file-activity.sh`)
- **`enable-file-activity-policy-berserker.sh`** - Enable file activity policy for `/tmp/data/` paths

See `scale/dev/` for the implementation details.

## Usage

### Quick Start

```bash
cd /home/jvirtane/go/src/github.com/stackrox/stackrox/scale/dev

# Set required environment variables
export PAGERDUTY_INTEGRATION_KEY="dummy-key-for-dev-testing"

# Run a single test (1 sensor, 600s runtime, 100 events/sec, no policy)
./perf-test-file-activity-berserker.sh 1 600 "file-activity-100" false

# Run with policy enabled
./perf-test-file-activity-berserker.sh 1 600 "file-activity-100" true
```

### Full Test Suite

Run all 5 event rates with and without policy (10 tests total):

```bash
cd scale/dev

for rate in 100 500 1000 2500 5000; do
  echo "Testing file-activity-${rate} without policy..."
  ./perf-test-file-activity-berserker.sh 1 600 "file-activity-${rate}" false

  echo "Testing file-activity-${rate} with policy..."
  ./perf-test-file-activity-berserker.sh 1 600 "file-activity-${rate}" true
done
```

### Generate Comparison Plots

The plotting scripts work with both fake workload and berserker results:

```bash
cd scale/dev

# Generate comparison plots across all test runs
python3 plot-batch-comparison.py perf perf/berserker_comparison

# View results
ls -lh perf/berserker_comparison/*.png
```

## Comparison with Fake Workload

| Aspect | Fake Workload | Berserker |
|--------|--------------|-----------|
| Event source | Sensor generates internally | Real file ops via eBPF |
| Path | `/etc/security`, `/var/log`, etc. | `/tmp/data/` |
| Deployment | ConfigMap mounted to sensor | DaemonSet pods |
| Scaling | Fixed global rate | Per-node DaemonSet |
| Realism | Synthetic events | Production-like events |
| Collector | Bypassed | Required (collector DaemonSet) |

## Troubleshooting

### Pods not starting

Check DaemonSet status:
```bash
kubectl get daemonset -n stackrox
kubectl describe daemonset berserker-file-activity-file-activity-100 -n stackrox
```

Check pod logs:
```bash
kubectl logs -n stackrox -l app=berserker-file-activity-file-activity-100
```

### Event rate mismatch

Verify the number of nodes matches the expected 3:
```bash
kubectl get nodes
```

If you have more or fewer nodes, the total event rate will scale accordingly. Adjust the rates in the `.ber` files if needed.

### No events reaching sensor

Verify collector is running:
```bash
kubectl get daemonset collector -n stackrox
kubectl get pods -n stackrox -l app=collector
```

Check collector logs:
```bash
kubectl logs -n stackrox -l app=collector -c collector
```

## Cleanup

Remove all berserker resources:
```bash
cd scale/dev
./cleanup-berserker.sh "" stackrox
```

Or remove a specific workload:
```bash
./cleanup-berserker.sh file-activity-100 stackrox
```
